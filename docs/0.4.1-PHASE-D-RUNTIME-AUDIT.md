# Bottles RetroCD 0.4.1 — Phase D runtime audit validation

Target validation date: **2026-09-11**

Target environment used for the real-machine gate:

- CachyOS / KDE / Wayland host;
- Bubblejail **0.10.4 AUR**;
- Bottles instance `Bottles`;
- dedicated AMD Radeon RX 9070 XT selected;
- XWayland compatibility path;
- network OFF;
- standard gamepad OFF for the runtime-surface snapshots;
- Discworld Noir three-disc set for optical/multidisc validation.

## D-Bus / dconf conclusion

The installed Bubblejail 0.10.4 implementation grants host dconf only from:

```toml
[gnome_toolkit]
dconf_dbus = true
```

The previous RetroCD audit incorrectly inspected `xdg_desktop_portal.dconf_dbus`; the effective key is `gnome_toolkit.dconf_dbus`.

With `gnome_toolkit.dconf_dbus=true`, the active `xdg-dbus-proxy` command line contained:

```text
--filter
--talk=ca.desrt.dconf
```

Bottles was then proved to run with:

```text
GSETTINGS_BACKEND=keyfile
```

and the private-HOME settings file:

```text
$HOME/.config/glib-2.0/settings/keyfile
```

was observed changing when a harmless Bottles preference changed. The preference persisted across a complete Bottles close/reopen.

After changing the Bubblejail profile to:

```toml
[gnome_toolkit]
dconf_dbus = false
```

all of the following were proved simultaneously:

- Bottles preferences still persist via the keyfile backend;
- the session bus exposes only `org.freedesktop.DBus`;
- `ca.desrt.dconf` introspection fails with `ServiceUnknown`;
- the effective proxy contains `--filter` and no dconf `--talk`/`--call` grant;
- RetroCD GPU and Retro Optical pre/post launch gates remain PASS;
- Discworld Noir remains functional under XWayland with network OFF.

Therefore host dconf access is unnecessary for this RetroCD configuration and **must remain disabled**. Missing evidence must not be promoted to PASS.

## Normal runtime-surface snapshot

Validated with multidisc live OFF and raw optical device OFF.

Expected/observed surface:

- session D-Bus: only `org.freedesktop.DBus`;
- system D-Bus: only `org.freedesktop.DBus`;
- runtime sockets: Bubblejail session/system proxies, PulseAudio, Wayland, X11 only;
- network: loopback only, no routes;
- devices: selected DRM card/render node only;
- `/dev/srX`, `/dev/sgX`, `/dev/vhba_ctl`, hidraw and unrelated input hidden;
- proxy policy: `--filter`, no dconf grant.

## Live multidisc delta

Discworld Noir live multidisc was validated with a saved 3-disc set.

At launch:

```text
multidisco live · cache RO 3/3
```

The live path intentionally exposes the exact active optical block device while cached CDEmu drives stay host-side.

Observed runtime device surface on Disc 1:

```text
block /dev/sr0 11:0
char /dev/dri/card1 226:1
char /dev/dri/renderD128 226:128
```

After a live swap from Disc 1 to Disc 2:

- the visible device remains the same `/dev/sr0`;
- `/mnt/cdemu` follows the newly selected RO mount;
- no cached `/dev/sr1+` device appears in the jail;
- no `/dev/sgX` appears;
- D-Bus, sockets, network and DRM surface remain unchanged;
- dconf remains blocked;
- closing Bottles triggers automatic cache cleanup and reports successful CDEmu cache removal.

This proves that the live multidisc delta is limited to the single exact active `/dev/srX` required by Wine.

## Process / file-descriptor / environment hygiene

A real runtime scan over visible `/proc/*/fd` reported:

```text
FD_SOSPETTI= 0
```

for paths matching removable-media trees, `/dev/sg*`, `/dev/vhba_ctl`, `.ssh`, or `.gnupg`.

A second scan inspected process environment **variable names only** and reported:

```text
VAR_SENSIBILI= 0
```

for common secret-bearing names/prefixes/suffixes including GitHub, SSH agent, GPG, AWS, Kubernetes, token, secret, password and API-key variables.

Static review also confirmed:

- verifier worker uses `--clearenv` and `close_fds=True`;
- updater worker uses `--clearenv` and `close_fds=True`;
- exact-node gamepad namespace FDs use `O_CLOEXEC`;
- CDEmu ownership lock uses `O_CLOEXEC`;
- the normal Bottles launch relies on Python's safe POSIX default of closing non-standard inherited FDs; no real leak was observed.

No speculative refactor is justified solely to restate already-safe defaults before the final 0.4.1 regression.

## Phase D verdict

**PASS.**

Runtime-surface hardening is considered target-validated with these invariants:

1. host dconf blocked and keyfile persistence proven;
2. D-Bus proxy fail-closed and filtered;
3. normal runtime surface minimal;
4. live multidisc adds only the exact active `/dev/srX`;
5. cached optical drives and SCSI generic nodes remain hidden;
6. no suspicious FD or common secret-bearing environment variable was observed in the jail;
7. GPU, XWayland, audio and Retro Optical compatibility remain intact.

The remaining work before 0.4.1 release consideration is consolidation/regression plus the complete Phase E package/install/uninstall-preservation gate. No merge or release is automatic; owner approval remains required.
